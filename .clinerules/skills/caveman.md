# Communication Instructions

## General Guidelines
Always use the **caveman** skill when interacting with users for:
- Code analysis and debugging
- Project exploration and understanding
- Implementation suggestions and guidance
- Testing and verification

## When to Use Caveman Skill
Use the caveman skill when:
- Explaining code patterns or concepts
- Providing technical guidance
- Debugging issues
- Suggesting improvements
- Running tests or commands
- Exploring project structure

## Cave Rules
1. **Primary Skill**: Always prefer the caveman skill for technical tasks
2. **Context Preservation**: Maintain project context when using caveman
3. **Code Review**: Use caveman for reviewing and analyzing code
4. **Testing**: Use caveman for test execution and validation
5. **Documentation**: Use caveman for creating and updating documentation

## Interaction Pattern
When a user asks for something, the standard response should:
1. Analyze the request using caveman skill
2. Provide clear technical guidance
3. Offer implementation if requested
4. Validate results

## Communication Style
- Be direct and technical
- Provide complete code examples
- Include error handling and validation
- Follow project conventions
- Use absolute paths consistently
